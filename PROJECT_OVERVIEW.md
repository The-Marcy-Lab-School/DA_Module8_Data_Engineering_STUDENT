# Project Overview: Data Engineering Pipelines & Delivery

## The objective

Build a real, scheduled, monitored, automated ETL/ELT pipeline in
**Apache Airflow** (via **Astro CLI**) that ingests from a real external
source, transforms the data, and loads it into your own **Module 3/7**
data warehouse. Delivered with a version-controlled, peer-reviewed
GitHub repository (a real feature-branch/pull-request workflow with a
real partner) and a written project backlog/timeline written *before*
you start building, not after.

## Why it matters

This is the first project in the program that's genuinely operational,
not just analytical — a pipeline that has to keep running correctly
without you watching it, recover from real failures, and alert someone
when it can't. It's also the first project with a real, required partner
collaboration component graded in its own right (not just "work in a
group if you want to") — the same feature-branch/PR review workflow real
data teams use every day. **Module 9** builds on this same orchestration
instinct at cloud/distributed scale.

## Deliverables at a glance

- A real Airflow DAG, on a real schedule, running end-to-end with no
  manual intervention once triggered.
- Retries configured **and genuinely tested** against a real simulated
  failure — not just configured and assumed to work.
- Structured logging at every task; ≥1 real alert that fires on failure.
- A real GitHub Actions CI check, its one real gap identified and fixed.
- A real project backlog (`backlog.md`): ≥5 sequenced tasks with real
  estimates, written before the build, task order justified against the
  real deadline/dependency chain.
- Your own git repo, built from scratch (no `.gitignore`/`LICENSE`
  given this time) — real feature-branch + pull-request workflow with a
  real partner, a real substantive review comment given and received, a
  real proactive milestone check-in.

## Skills you'll practice

- **ETL/ELT, Apache Airflow, Automation, Data Engineering** — a real,
  working, scheduled pipeline, not a diagram of one.
- **Monitoring & Observability** — real structured logs, a real alert.
- **CI/CD** — a real GitHub Actions workflow, a real gap found and
  closed.
- **Project Management, Prioritization** — a real backlog written first,
  task order justified against a real deadline.
- **Ownership & Accountability** — a real, proactive milestone check-in.
- **Collaboration & Teamwork, Git Version Control** — a real
  feature-branch/PR workflow, real peer review, given and received.
